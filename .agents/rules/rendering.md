# Рендер и визуальный стиль

Проект собирается **одним билдом под три рендерера**: Forward+ (desktop),
Mobile, Compatibility (web). Возможности проверяются через `RenderCaps`,
а не россыпью условий по коду.

## Ловушки, стоившие отладки

- **Не писать `ALPHA`** в непрозрачном spatial-шейдере: любое присваивание
  переводит материал в прозрачные, а те не принимают направленные тени и не
  пишут глубину. Для стекла — отдельный материал.
- **`SurfaceTool.generate_normals()` сглаживает** нормали совпадающих вершин.
  `MeshBuilder` вызывает `set_smooth_group(-1)` — без этого low-poly не бывает.
- **Передние грани — по часовой стрелке.** `MeshBuilder.tri()` принимает
  вершины в привычной CCW-нотации и разворачивает их сам, один раз.
- **Compatibility на macOS не рисует тени** от направленного света. Сцена
  обязана читаться без них: вершинное затемнение, контактные тени, туман.
- **Ambient нельзя оставлять чёрным** при `sky_contribution < 1` — ночь
  проваливается в чёрное.
- **`instance uniform` не работает в Compatibility/GLES3.** В скомпилированном
  шейдере движка `instance_uniforms_ofs` есть только в RD-бэкенде
  (Forward+/Mobile) — на вебе поле молча берёт значение по умолчанию. Для
  состояния, которое меняется на лету и должно работать на всех трёх
  рендерерах (например, свет ламп машины), — не instance uniform, а таблица
  готовых `ShaderMaterial` с обычными uniform (`core/car_lamp_materials.gd`):
  `material_override` меняется раз в кадр, draw calls не растут.
- **Читать `COLOR.a` можно свободно** — правило про ALPHA касается только
  записи в выходной `ALPHA` во фрагменте. Кодировать доп. информацию (тип
  поверхности: лампа/стекло/обычная панель) в альфе вершинного цвета —
  штатный приём, `SurfaceTool.commit()`/`index()` её не портят (см.
  `test_vertex_color_alpha_preserved`, `test_index_does_not_merge_vertices_with_different_alpha`
  в `tests/unit/test_mesh_builder.gd`). Сравнивать в шейдере — с допуском
  (`abs(v - x) < eps`), альфа проходит RGBA8-квантование при коммите меша.
- **`MultiMeshInstance3D` наследует `cull_back` от материала как обычно** —
  веер треугольников, поставленный «наизнанку» (обратная намотка), рисуется
  только с обратной стороны и с фронтальным `cull_back` невидим целиком, без
  ошибок в консоли. `MeshBuilder.shadow_disc()` один раз наступил на эти
  грабли — регрессия закрыта `test_shadow_disc_normals_point_up`. При
  добавлении нового веерного/лучевого примитива в `MeshBuilder` — сразу
  писать тест на направление нормалей, не только на форму и цвет.

## Геометрия

- Вся процедурная геометрия строится `MeshBuilder`: вершинный цвет вместо
  текстур, один палитровый материал на город, машины и пешеходов.
- Повторяющееся — в `MultiMeshInstance3D` с `use_colors`. Смена состояния
  (фаза светофора, ночная подсветка) — запись в инстанс или общий материал,
  а не обход узлов.
- Уникальная геометрия режется на чанки 128 м ради frustum culling.

## Проверка глазами

Headless не рендерит. Снимок сцены:

```
godot --path . tools/capture_runner.tscn -- \
  --scene res://tests/scenes/test_city.tscn --out /tmp/city.png --frames 55
tools/capture_style.sh res://tests/scenes/test_city.tscn   # все три рендерера
```

Утверждать, как что-то выглядит, без снимка — нельзя.
