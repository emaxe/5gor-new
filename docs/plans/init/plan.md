## Инвентарь портируемого функционала

Полный перечень — то, что должно оказаться в Godot-версии.

### Мир (`citygen.js`, 3129 стр.)
Детерминированный `mulberry32(20260805)` — город всегда одинаков.
Сетка 9×9 перекрёстков, шаг `CELL=64` м, координаты −256…+256 (81 перекрёсток).
Дорога `ROAD_W=12` (4 полосы), `HALF=6`, тротуар `SIDE=4`. Границы города ±308
плюс северный «отросток» серпантина `z ∈ [−470, −300], |x| ≤ 85`.

Рельеф — только Машук: `hill {x:0, z:−448, r:155, hc:66, top:58}` + вторая
вершина `peak2 {x:55, z:−500, r:70, hc:46, top:40}`, сопряжённые smin/smax,
плюс «полка» серпантина полушириной 3.6 м с откосом 8 м.

Порядок сборки мира (`World.build()`, 22 шага): ground → roads → crosswalks →
mountains → hillAndSerpentine → buildings → specials → trees → lamps → props →
fuelStations → trafficLights → cableCar → signs → streetBenches → planters →
busStops → wasteBins → kiosks → playgrounds → parkedCars → collectPickupPoints →
buildBuildingHash.

Достопримечательности (`_specials`): монумент орла, пятигорский трамвай,
трамвайная остановка, статуя Остапа Бендера, телебашня, городская стела,
парк Цветник, озеро Провал, рынок «Лира», ж/д вокзал (с подвижным составом),
Нарзанные ванны, беседка «Эолова арфа», грот Лермонтова, канатная дорога.

8 районов с порогом рейтинга: Центр 0, Курортный 0, Привокзальный 0,
Провал 15, Рынок «Лира» 30, Санатории 45, Машук 60, Вокзал 75. У каждого —
палитра фасадов (5 цветов), диапазон высоты зданий, плотность.

Светофоры: цикл 16 с со сдвигом на перекрёсток. Ось z: t<6 зелёный, t<8 жёлтый,
иначе красный. Ось x: t<8 красный, t<14 зелёный, иначе жёлтый. Пешеходный
зелёный, когда машинам красный.

Коллайдеры: `buildings[]` AABB + spatial hash 16 м, `propsAABB[]` hash 10 м
(с полем `y` — проезжаемая высота для арок), `circleColliders[]` (озеро, фонтаны).

Точки подачи: вдоль каждой дороги каждые 48 м по обеим сторонам, смещение
`HALF + SIDE/2 = 8` м от оси, кроме точек ближе `HALF` к поперечной дороге.

### Машина игрока (`player.js`, `carmodel.js`)
Аркадная **кинематическая** физика (не rigid body), полу-неявный Эйлер:
- Продольная: `accelV` из газа/тормоза/сопротивления, `fwdSpeed` клампится
  `[−7, maxSpeed]`.
- Руление: `steerRate = steer * clamp(|fwd|/12,0,1) * (1 − |fwd|/(maxSpeed*1.6))`,
  ручник ×1.5, инверсия при заднем ходе, самовыравнивание `latSpeed*0.06`.
- Сцепление: `grip = gripMul * weatherGrip * stats.grip * (handbrake?0.28:1)`,
  `latSpeed *= max(0, 1 − grip*2.2*dt)`, `gripMul = (onRoad?1:0.55)*(склон?0.85:1)`.
- Топливо `(0.11 + 0.10*|fwd|/maxSpeed)*dt`, грязь `dt*0.0012*(1+speed/20)`.
- Стиль вождения (только с пассажиром, раз в 1 с):
  `jerk = min(1,|accelV|/40)*0.7 + min(1,slip)*0.5; style −= jerk*0.03`.
- Коллайдер — **капсула из 3 кругов** вдоль оси: `rc = (w/2)*1.03`,
  смещения `[+sep, 0, −sep]`, `sep = len/2 − w/2`.
- Разрешение: статика — отскок ×1.5, трафик — ×1.35 при `vn < −2`.
  Урон `impact²*0.018/armor`. Глохнет при `impact>20 && damage>60` (2.5 с).
- Наезд на пешехода: `|speed|>4.2 && relVel>1.5` — сбит; `>1.0 && >0.2` — уворот.

7 моделей авто (maxSpeed/accel/brake/grip/armor/tank/capacity/steer),
6 апгрейдов (`base * 1.7^lvl`, capacity ×1.8), тюнинг: 7 цветов, 3 стиля дисков,
спойлер, 2 боди-кита, 4 декали.

### Пеший режим (`playerped.js`)
Выход при `|speed| ≤ 1.5` через левую дверь (офсеты 1.5/2.0/2.5/3.0).
Ходьба 3.1 / бег 5.8 м/с, прыжок 6.5 при гравитации 20. Удар: радиус 2.0,
конус ±60°, кулдаун 0.8 с, паника свидетелей 8 м, штраф 150 ₽ + полицейский
500 ₽, −5 рейтинга. HP 3, стан 0.6 с, нокаут 2.0 с. Радиус коллизии 0.35.

### Трафик (`traffic.js`)
20 типов транспорта с весами (sedan 16 … limo 0.6), гарантированно минимум одна
полицейская машина. `trafficCount = 14 × density`. Движение «на рельсах»:
`{axis, coord, pos, dir}`, мировая позиция — правая полоса (±2.5 от оси).
10 правил ИИ по убыванию приоритета: пропсы → уступить спецтранспорту →
дистанция до впереди идущего → пешеход на зебре → наезд → поворот →
наезд на игрока-пешехода → приоритет на перекрёстке → игрок впереди →
светофор (`brakeDist = speed²/20`, `stopLine 6.5`; агрессивные 4% с шансом 30%
проезжают на красный, если перекрёсток свободен).
Повороты — кубическая Безье: 58% прямо, 22% направо, 20% налево.
Разворот на `|pos| > 250`. Респавн при удалении >260 м.
Мигалки полиции/скорой — противофаза, период 0.6 с.

### Пешеходы (`peds.js` 2097, `pedgraph.js`, `pedavoid.js`)
`pedCount = 34 × density`. 13 человеческих архетипов + собаки/кошки (~25%).
Скорости 1.2–5.0 м/с по архетипу. Режимы: walk/run/wait/cross/turn/flee/kick/idle.
LOD-зоны: ≤110 м полный ИИ (Dijkstra по `PedGraph`, не более 2 активаций за тик),
110–150 м упрощённое движение, >210 м телепорт-респавн (30 попыток: ≥50 м от
игрока, вне поля зрения ±75°).
`PedGraph`: узлы тротуаров + середины лент + центры переходов; стоимости рёбер
walk 0.5, turn 1.5, cross 1, jwalk 3. POI привязаны к узлам (≤40 м).
Нарушители 8% (ночью ×1.4, потолок 0.35). Животные всегда игнорируют светофоры.
Реакции: ругань при подрезании (архетипный пул), пинок при `dist<2.4`,
бегство, сбитие/уворот. Болтовня раз в 16–36 с при дистанции <45 м, облачко
видно только в поле зрения (±75°, 60 м).

### Заказы (`orders.js`, `dialogues.js`)
8 типов: normal 1.0, urgent 1.6 (75 с), vip 1.5, package 1.15, drunk 1.35,
group 0.9, race 1.9 (90 с), tour 2.0. Разные вероятности днём и ночью.
5 сюжетных миссий (grandma/doctor/race/tour/night), шанс 30% вместо обычного
заказа, по одной за смену.
Геометрия: пикап в 60% случаев в 40–240 м от игрока, дроп ≥150 м от пикапа,
дистанция манхэттенская.
Оплата: `estPay = (120 + dist*1.35) * mult`; при завершении — бонус за время
до +35%, ночной ×2, рейтинг ≥60 ×1.15, чаевые `90*style*(vip?1.5:1)*(1−dirt*0.5)`,
битый груз ×0.5. Комбо `1 + min(streak,10)*0.05` (до ×1.5).
Оценка: `5 − round((1−style)*3)`, −1 при `dirt>0.4`, −2 при битом грузе,
−1 для VIP если <4; зажим `[1,5]`, текст из пула `REVIEWS`.
Диалоги: 32 имени пассажиров, аватары, `DIALOGUES` по типу заказа × событию,
`WEATHER_DIALOGUES`, `DISPATCHER_BRIEFS`, `DRIVER_DAY_NOTES`,
`PASSENGER_DRIFT_REACTIONS`, `PEDESTRIAN_SHOUTS`, `DRIVER_SHOUTS` — ~350 реплик.

### Бонусные механики
- **Дрифт**: `handbrake && slip≥0.5 && speed≥7.0`, ≥0.8 с →
  `min(200, 40 + (dur−0.8)*50)` ₽, `style += 0.05`.
- **Идеальная остановка**: торможение с ≥7.0 м/с до ≤0.8 при пиковом
  замедлении ≤9.5 м/с² с пассажиром → +50 ₽, `style += 0.08`.
- **Near-miss**: `speed ≥ 10`, зазор ≤1.2 м до авто / ≤1.0 м до пешехода без
  касания → 35 ₽ × множитель серии (2→×2, 5→×5, 10→×10, окно 8 с),
  `style += 0.04`. Флаг сбрасывается на 8 м.
- **Комбо заказов**: milestone-фидбек на 3/5/10.

## Известные дефекты оригинала — исправить при порте

Из `docs/code-quality-audit-2026-08-23.md` (часть уже исправлена коммитами
`1f25a63`, `ae1292b`) и собственной проверки:

1. **`utils.showError()` — no-op**: ищет `#err-msg`/`#error-screen`, а в разметке
   `#err-text`/`#error-overlay`. Все ошибки игрового цикла молча проглатываются.
2. **Часы не оборачиваются по модулю 24**: `hour = minutes/60` без `% 24`,
   после 720 с показывает 33:00 и растёт. «Ночь» становится вечной.
3. **Прямые правки `this.money`** (эвакуатор, заправка, апгрейд, покупка,
   ремонт, мойка) не эмитят `money:changed` — нет VFX и подписчиков.
4. **Пеший километраж** не идёт в lifetime-статистику — ачивка km_500 его не видит.
5. **O(n²)+O(n×m) в `traffic.update`** каждый кадр: вложенные переборы машин
   и пешеходов, линейный поиск ближайшего из 81 перекрёстка, перебор всех
   светофоров. Терпимо при 14 машинах, не масштабируется.
6. **Draw-call explosion**: ~240–300 draw calls, каждое здание отдельным мешем.
7. **Покадровые аллокации** в hot path: `_avoidStatic`, `citygen.update`,
   `_updateInteract` (новый объект каждый кадр ломает dirty-check и пишет в DOM
   60 раз/сек), строковые ключи spatial hash.
8. **Синхронная блокирующая генерация мира** 100–300 мс до первого кадра.
 9. ~~**`chaseLevel 4` не реализован** — погоня полиции объявлена, но её нет.~~
    Реализовано на этапе 11: `PoliceManager._update_chase` выбирает ближайший
    патруль, `TrafficManager._update_chasing` ведёт его к игроку по графу.
10. **Именование `peds.cars`** для массива пешеходов.
11. **Несовпадение ключей** `ratingPerOrder.tourist` vs тип заказа `tour`
    (срабатывает fallback `|| 8`).
12. Мёртвый код в `config.js` (`urgentMult`/`vipMult`/`groupMult`/`touristMult`,
    `CFG.N`, `pedPunchKnockSpeed`, часть `ratingFail`, `TUNING.spoiler`,
    `desc` у LANDMARKS, `name`/`rain` у WEATHER_DEFS).

### Автолоады (5 штук)

| Autoload | Ответственность | Почему автолоад |
|---|---|---|
| `SignalBus` | Только lifecycle-события, < 15 сигналов | Разрывает циклы между системами |
| `GameState` | Деньги, рейтинг, день, час, погода, `shift_stats`, `lifetime_stats` — **единственный владелец** | Читают все, меняет только он через методы |
| `SaveManager` | `user://save.cfg`, `user://achievements.cfg`, версионирование, миграции | Нужен до загрузки сцен |
| `Settings` | Графика/громкость/водитель + применение к `Viewport`/`AudioServer` | Применяется до создания мира |
| `AudioDirector` | Шины, пул `AudioStreamPlayer3D`, voice-budget, радио | Живёт между сценами |

Сигналы `SignalBus` (ровно 14, остальное — локальные сигналы узлов и
feature-шины `CombatBus`/`OrderBus`):
`shift_started(day)`, `shift_ended(stats)`, `state_changed(from, to)`,
`money_changed(value, delta)`, `rating_changed(value, delta)`,
`order_accepted(order)`, `order_completed(result)`, `order_failed(order)`,
`crash(impact, victim)`, `ped_hit(pos)`, `police_fine(violation, amount)`,
`police_escaped(peak_level)`, `achievement_unlocked(id)`, `toast(text, kind)`.

**Ключевое правило**: все изменения денег и рейтинга — только через
`GameState.add_money()` / `add_rating()`. Это чинит дефект №3 оригинала
(прямые правки `this.money` без события).

### Слой данных

Все константы из `config.js`, `traffic.js:TRAFFIC_TYPES`, `orders.js:ORDER_META`
+ `MISSION_TEMPLATES`, `achievements.js:ACHIEVEMENTS`, `dialogues.js` (~350 реплик),
`peds.js` (пулы реплик по архетипам) переносятся в типизированные `Resource`
с `class_name` и `.tres`-экземплярами. Никаких «магических» словарей в коде.

Ловушка Godot №1 — `@export`-ресурсы шарятся между экземплярами. Правило проекта:
- **Read-only определения** (`CarData`, `TrafficTypeData`, `PedArchetypeData`,
  `OrderTypeData`) никогда не мутируются в рантайме — их можно шарить.
- **Мутируемое состояние** (текущие статы машины после апгрейдов, состояние
  заказа, состояние пешехода) живёт в отдельных `RefCounted`-объектах,
  создаваемых из `Data` через `make_runtime()`. Ни один `.tres` не пишется
  в рантайме.
- Где мутация ресурса неизбежна — `resource_local_to_scene = true` + `duplicate()`.

`RefCounted` вместо `Node` для: `TrafficCar`, `PedAgent`, `Order`,
`DamageRequest`, `RouteQuery`. Это снимает оверхед SceneTree на ~50 сущностей.

### Физика машины — портируем 1:1, без VehicleBody3D

`VehicleBody3D` даст совершенно другое ощущение управления и сломает весь
баланс (дрифт-пороги, near-miss, идеальная остановка калиброваны под текущую
модель). Решение: `CharacterBody3D` с полностью ручной интеграцией
в `_physics_process(delta)` (фикс. 60 Гц), формулы переносятся дословно.

Изменения при переносе:
- Оригинал использует переменный `dt` с клампом 0.05. В Godot шаг фиксированный
  1/60 — это **улучшение** (детерминизм), но нужно перепроверить:
  - `latSpeed *= max(0, 1 - grip*2.2*dt)` — корректно при любом dt;
  - `lerp(x, y, 0.14)` для кренов и `lerp(x, y, 0.15)` для `steerVisual` —
    **frame-rate dependent**, переводим в `lerp(x, y, 1.0 - pow(1.0 - 0.14, dt*60.0))`;
  - камера уже кадронезависима (`1 - 0.001^dt`) — переносится как есть.
- Капсула из 3 кругов: не `CapsuleShape3D`, а **три `SphereShape3D` в одном
  `PhysicsShapeQueryParameters3D`**-цикле через `PhysicsDirectSpaceState3D
  .intersect_shape()`, ровно как в оригинале (перед/центр/зад, `rc = w/2*1.03`,
  `sep = len/2 - w/2`). Разрешение столкновений — своё (`vn*1.5` для статики,
  `vn*1.35` для трафика), не движковое. Тело машины — `CharacterBody3D` с
  выключенным `move_and_slide`, перемещение через прямое присваивание позиции.
- Здания/пропсы: `StaticBody3D` с `BoxShape3D` не нужны — сохраняем собственный
  spatial hash (числовой ключ `(cx+512)*1024+(cz+512)` вместо строкового,
  чинит дефект №7). Физические тела ставим только там, где нужен движок
  (ничего критичного не нашлось).

### Мир: генерация и draw calls

Целевой бюджет: **< 200 draw calls** на кадр (против 240–300 в оригинале),
mobile — < 150.

- **Здания**: не меш на здание, а **чанки 128×128 м**. Внутри чанка все стены
  и крыши собираются `SurfaceTool` с `set_color()` в один `ArrayMesh` с
  единым материалом `vertex_color_use_as_albedo = true`. 8×8 кварталов →
  ~25 чанков вместо ~250 мешей. Окна — не текстура на здание, а отдельный
  emissive-сабмеш того же чанка (ночная подсветка через один
  `emission_energy` на материал чанка).
- **Повторяющийся пропс** (деревья, фонари, светофоры, урны, кусты, лавки,
  вазоны, разметка, зебры, припаркованные машины) — `MultiMeshInstance3D`
  с `use_colors = true` (прямой аналог `setColorAt`). Светофоры — 4 MultiMesh
  (столб / корпус / линзы авто / линзы пешеходные), смена цвета через
  `set_instance_color` только при смене состояния.
- **Уникальные достопримечательности** — отдельные `.tscn`, собранные один раз
  скриптом-генератором и **сохранённые на диск** как `.res`/`.tscn`
  (не пересобираются в рантайме). Это резко ускоряет загрузку и позволяет
  дорабатывать модели вручную в редакторе — прямой путь к «улучшенным моделям».
- **Гора Машук**: `ArrayMesh` из той же функции `height_at()`, что используется
  физикой — как в оригинале, визуал и коллизия совпадают пиксель-в-пиксель.
- **Генерация в фоне**: `WorkerThreadPool` строит `ArrayMesh` и MultiMesh-буферы
  off-tree, узлы добавляются через `add_child.call_deferred()`. Экран загрузки
  с прогрессом по 22 генераторам. Это чинит дефект №8 (блокировка 100–300 мс).
- **`height_at()`, `on_road()`, `dist_to_road()`, `dist_to_serp()`** — чистые
  функции без узлов, покрываются юнит-тестами (как `gps.js`/`pedgraph.js`
  в оригинале).

### Трафик и пешеходы — data-oriented

Не по узлу на NPC с `_process`, а **один менеджер** с массивом `RefCounted`-
агентов, обновляемых в одном цикле (правило «NEVER `_process` для 1000+
сущностей», здесь — 14 машин + 34 пешехода, но архитектура должна выдержать
рост плотности до ×3 на десктопе).

- Визуал NPC — `MultiMeshInstance3D` по типу транспорта (все седаны в одном
  MultiMesh) для дальних, и отдельные узлы для ближних (нужны анимация колёс,
  мигалки, свет). Порог — 60 м.
- **Бакетизация**: у машин и пешеходов уже есть поля `axis` и `coord` —
  строим `Dictionary` бакетов `(axis, coord)` и обновляем его раз в кадр.
  Соседей ищем только в своём бакете. Перекрёстки — индекс
  `round(pos/64)` вместо линейного перебора 81 узла. Светофоры — индекс
  по перекрёстку. Это чинит дефект №5 (O(n²)).
- **Пешеходы**: собственный `PedGraph` (портируем `pedgraph.js`), **не**
  `NavigationServer3D`. Причины: граф уже задан регулярной сеткой, стоимости
  рёбер кодируют правила ПДД (`walk 0.5 / turn 1.5 / cross 1 / jwalk 3`),
  навмеш этого не выразит; плюс детерминизм и тестируемость. `NavigationServer3D`
  избыточен и дороже.
  Обход препятствий (`pedavoid.js`) — портируем как есть, но с двумя
  константными массивами уровня модуля вместо покадровой аллокации (дефект №7).
- **LOD-зоны** сохраняем: ≤110 м полный ИИ (не более 2 Dijkstra за тик),
  110–150 м упрощённое движение, >210 м респавн.

### Модели и визуальный стиль (low-poly / stylized)

Направление: чистые формы, плоские грани, насыщенная палитра оригинала
(она уже хорошо подобрана), выразительный силуэт, cel-подобный свет.

- **Машины**: портируем генератор `carmodel.js` в `car_builder.gd` на
  `SurfaceTool`, но **с повышенной детализацией**: фаски на кузове (chamfer
  вместо острого бокса), реальные колёсные арки, отдельный меш стёкол с
  плоским отражением, номерной знак, детальные фары/стопы. Плоский шейдинг —
  через `SurfaceTool.set_smooth_group(-1)`. Трафик — один `ArrayMesh` на тип
  с vertex colors (1 draw call), игрок — узлы с отдельными материалами для
  света и тюнинга. Кэш геометрий по детерминированному ключу, как в оригинале.
- **Пешеходы**: вместо боксов на пивотах — низкополигональные фигуры
  (~300–500 трис) с `Skeleton3D` (6–8 костей: таз, торс, голова, 2 руки,
  2 ноги) и `AnimationTree` + `BlendSpace1D` (idle ↔ walk ↔ run) плюс
  one-shot клипы (kick, knockdown, flee). Скелет и клипы делаются скриптом —
  Blender не нужен. Это заметный апгрейд против ручного `rotation.x = sin(...)`.
  Дальние пешеходы — MultiMesh со статичной позой.
- **Водитель игрока** — самая детальная модель (как и в оригинале), с
  кастомизацией (живот, кепка, 4 палитры).
- **Освещение**: `DirectionalLight3D` (солнце, тени 2048 на desktop / 1024
  mobile / off на web-low) + `WorldEnvironment`. Ночью — реальные
  `OmniLight3D` у фонарей **только в радиусе 60 м от игрока** (пул на 12 ламп,
  переиспользуются), остальное — эмиссивные пятна MultiMesh, как в оригинале.
  Фары — `SpotLight3D` с проектором-текстурой.
- **Небо**: `ProceduralSkyMaterial` с интерполяцией по `SKY_TABLE` (8 опорных
  часов) вместо плоского цвета — сразу заметный апгрейд. Луна и звёзды —
  на слое неба.
- **Пост-обработка** (то, чего в оригинале нет вовсе): `glow` (фары, окна,
  мигалки, неон), `adjustment` (контраст/насыщенность для «плотной» палитры),
  SSAO на desktop, `fog` + `volumetric_fog` на desktop для погоды `fog`.
  Опциональный outline-пост для чистого low-poly-стиля (тонкая тёмная
  обводка по депту/нормали) — включается пресетом, не работает на
  Compatibility → там отключается.
- **Мокрый асфальт**: свой `road_wet.gdshader` с интерполяцией roughness/
  metalness по `wetness` + экранные отражения фар (`SCREEN_TEXTURE` на
  desktop, простое отражение цвета неба на mobile/web).
- **Дождь**: `GPUParticles3D` вместо шейдера на Points, следует за камерой.

### Рендерер по платформам

В `project.godot`:
```
rendering/renderer/rendering_method                = "forward_plus"
rendering/renderer/rendering_method.mobile         = "mobile"
rendering/renderer/rendering_method.web            = "gl_compatibility"
```
Каждый эффект гейтится по `RenderingServer.get_rendering_device() != null` /
`OS.has_feature("mobile")` / `OS.has_feature("web")`. Пресеты графики
(low/medium/high/custom) портируются 1:1, `pixelRatio` + `pixelBudget`
заменяются на `Viewport.scaling_3d_scale` + автоподбор под бюджет пикселей
(та же формула `sqrt(budget/(w*h))`).

Все шейдеры пишутся так, чтобы компилироваться и на Compatibility
(без `SCREEN_TEXTURE`-зависимостей в базовой ветке, без compute).

### Звук

Портировать Web Audio/Tone.js в реальном времени через `AudioStreamGenerator`
на GDScript — плохая идея: побайтовая генерация в скрипте съест бюджет CPU,
особенно на mobile/web. Решение — **гибрид**:

1. **SFX (30 эффектов)** — синтезируются **один раз при первом запуске**
   скриптом `sfx_synth.gd` в `AudioStreamWAV` и кэшируются в
   `user://audio_cache/` (с версией). Дальше играются обычными
   `AudioStreamPlayer3D` из пула. Формулы синтеза переносятся из `audiosfx.js`
   дословно. Ноль внешних файлов — как в оригинале.
2. **Двигатель** — не сэмпл, а 2–3 зацикленных `AudioStreamWAV` (низ/середина/
   верх), синтезированных так же, с кроссфейдом и `pitch_scale` по RPM.
   Плюс слои: скид, шины, ветер, тормоза, дребезг повреждения.
3. **Радио (6 станций)** — сэмплер + секвенсор: банк коротких
   one-shot `AudioStreamWAV` (kick, snare, hat, bass, lead, pad) на станцию,
   синтезируются при первом включении станции; `radio_sequencer.gd` играет
   паттерны по своему BPM через таймер на `AudioServer.get_time_to_next_mix()`
   (без дрейфа). Кроссфейд станций, ducking на речь/аварии — через
   `AudioEffectVolumeDB` автоматизацию на шине `Music`.
4. **Шины `AudioServer`** — ровно 7 из оригинала: Master, Music, SFX, Engine,
   Ambient, UI, Voice, с теми же дефолтами. Лимитер и реверб — штатные
   `AudioEffectLimiter` / `AudioEffectReverb` (заменяют процедурную IR).
   Voice-budget и кулдауны портируются в `audio_director.gd`.

## Уточнения после детального проектирования (приняты)

Решения, уточняющие разделы выше — при расхождении приоритет у этих.

1. **Соглашение «вперёд».** Three.js: `fwd = (sin(h), cos(h))`, 0 = +Z.
   Godot-нативный forward = `-Z`. Меши авторим носом в `-Z`, а формулы
   переносим буквально через единственный конвертер `core/heading.gd`
   (`forward(h) -> Vector3(sin(h), 0, cos(h))`, `basis_of(h) -> Basis(UP, h + PI)`).

2. **Перенос данных — скриптом, не руками.** Тысячи чисел и ~350 русских
   реплик вручную перенести без расхождений невозможно.
   - `/Users/maksimklisin/Desktop/_JS/5gor/tools/dump_data.mjs` — импортирует
     `config.js`, `traffic.js`, `orders.js`, `achievements.js`, `dialogues.js`,
     `peds.js` и пишет `dump/*.json`.
   - `res://tools/import_json.gd` (`@tool`, `godot --headless --script`) читает
     JSON и генерирует `.tres` через `ResourceSaver.save()`.
   Импорт воспроизводим: правка баланса в оригинале → перегенерация за секунды.

3. **Капсула из 3 кругов — штатными средствами.** `CharacterBody3D` допускает
   несколько `CollisionShape3D`-детей. Три `CapsuleShape3D` (общий ресурс шейпа)
   на `z = -sep, 0, +sep` дают в горизонтальном сечении ровно три круга
   радиуса `rc` — точный эквивалент оригинала. `move_and_slide()` +
   `MOTION_MODE_FLOATING`, разбор импульса через `get_slide_collision()`
   с теми же коэффициентами (`1.35` для трафика, порог `vn < -2`).
   Капсула, а не цилиндр — в Jolt цилиндр даёт артефакты на рёбрах.

4. **Коллизии города — `PhysicsServer3D` без нод.** Один статик-боди на чанк,
   тысячи шейпов, кэш `BoxShape3D` по округлённым до 0.25 м габаритам
   (~200 уникальных шейпов на весь город). Земля/дороги/склон Машука —
   **без коллайдера**, Y берётся из `CityField.height_at()` (O(1) билинейная
   выборка). `Area3D` — только на 4 заправки, гараж и точки активного заказа
   (≤ 15 штук).

5. **Анимация толпы в MultiMesh.** `use_custom_data = true`, в
   `INSTANCE_CUSTOM.x` — фаза шага, `.y` — скорость; шейдер
   `multimesh_ped.gdshader` качает вершины в `vertex()` по маске в `UV2.x`.
   200 анимированных пешеходов за ~14 draw calls и ноль CPU.
   `Skeleton3D` + `AnimationTree` — **только** для near-LOD (≤ 45 м, пул из 20)
   и для игрока.

6. **Пешеходный граф — `AStar3D`, два экземпляра.** `graph_legal` (без
   jwalk-рёбер) для законопослушных и `graph_all` для нарушителей —
   переключение выбором объекта, ноль условий в горячем цикле. Встроенный
   C++-A* вместо ручного BFS оригинала.

7. **Стиль без screen-space outline.** Depth-based outline недоступен в
   Compatibility. Вместо него: `render_mode diffuse_toon, specular_toon`
   (работает во всех трёх рендерерах) + flat-нормали + **inverted hull**
   (`cull_front`, `VERTEX += NORMAL * width`) только на «героях» —
   машина игрока, пеший игрок, активный пассажир, маркер заказа, полиция
   (~6 объектов, +6 draw calls). Псевдо-AO — вершинным затемнением при
   мешировании (низ зданий, основания пропсов), стоит ноль.
   Плотность палитры — через LUT `color_correction` (`lut_day.png` /
   `lut_night.png`, кроссфейд по часу).
   **Проверить `diffuse_toon` на Compatibility на этапе 2**; если деградирует
   в Lambert — запасной путь `unshaded` + ручной расчёт по глобальному
   uniform направления солнца.

8. **Ночь: `LightPool` вместо света на каждый фонарь.** 12 (web) / 24 (mobile) /
   40 (desktop) `OmniLight3D`, переназначаемых на ближайшие фонари; перепривязка
   с гистерезисом раз в 0.5 с и плавным fade энергии. Всё остальное —
   emissive + `Environment.glow` (`SOFTLIGHT`, `bloom 0.15`).

9. **Генерация в три фазы с web-фоллбэком.**
   A (поток, только данные → `CityPlan` из `Packed*Array`) →
   B (поток, только математика над массивами → surface arrays) →
   C (главный поток, time-sliced ≤ 4 мс/кадр: `ArrayMesh`, MultiMesh,
   `PhysicsServer3D`). Фазы A и B пишутся так, чтобы работать и как
   `WorkerThreadPool.add_group_task`, и как time-sliced корутина — на
   однопоточном web всё уходит в корутины под загрузочным экраном.

10. **Аудио — уточнения.** Даккинг — штатным `AudioEffectCompressor` с
    `sidechain = "Voice"` на шине `Music`. Радио — lookahead-планировщик
    (0.15 с) поверх `AudioStreamPlaybackPolyphonic`. SFX — 3–4 варианта на звук
    в `AudioStreamRandomizer` вместо живого синтеза каждый раз. Кэш —
    `user://sfx_cache_v1/<hash>.res`, хэш = id + версия рецепта.

11. **Ввод — тач инжектится в тот же слой.** `Input.action_press(&"throttle", v)`
    из виртуального джойстика — тач становится ещё одним источником силы
    действия, а не параллельным путём. `Input.get_axis`/`get_action_strength`
    сами объединяют клавиатуру и аналоговые оси геймпада.

12. **Сохранения — атомарно и по 3 слотам.** Запись в `slot_N.save.tmp` →
    `DirAccess.rename_absolute()` (иначе убийство приложения на mobile портит
    слот). `user://settings.cfg` (`ConfigFile`) отдельно от слотов; ачивки
    дублируются в глобальный профиль, чтобы удаление слота их не стирало.
    На web проверять `OS.is_userfs_persistent()`, сохранять на
    `NOTIFICATION_WM_CLOSE_REQUEST` и `NOTIFICATION_APPLICATION_PAUSED`.

13. **Эмодзи в UI заменяем векторными иконками.** 🚕/⭐/😡 рендерятся
    по-разному на Android/Web и весят; свой атлас даёт стилевое единство.

14. **Дополнительные улучшения механик (сверх списка выше):**
    - **Плотность мира**: 14 машин / 34 пешехода — следствие O(n²), а не
      дизайна. Новая архитектура даёт 50–60 машин и 150–200 пешеходов той же
      ценой. Самое заметное улучшение на вложенный труд.
    - **Сохранение `world_seed` в слот**: город становится «своим», игрок
      выучивает маршруты — для игры про такси это основная кривая мастерства.
      Бонус: воспроизводимые баг-репорты.
    - **Модель спроса на заказы**: вес района × время суток (утро — вокзал,
      день — рынок, вечер — санатории, ночь — Машук) + «горячие точки»
      с временным множителем. Только поля в `DistrictData`, а даёт ритм смены.
    - **Прогресс достижений** (`track_stat` + `track_target`) — прогресс-бары
      бесплатно из декларативной схемы.
    - **Настраиваемая длина смены** (0.5× / 1× / 2×) — одна строка в `Clock`.

15. **Чего не делать** (соблазн, но вне рамок): физика подвески,
    разрушаемость, мультиплеер, редактор города.

## Принципы, взятые из проекта `capital` (по указанию пользователя)

Соседний Godot-проект `/Users/maksimklisin/Desktop/_JS/_games/capital` — симулятор
личных финансов, где город это фон. Трафик там намеренно декоративный (10 машин),
но **пешеходный граф, вызывные светофоры и ПДД-логика сделаны всерьёз** и
переносятся почти без изменений. Город 8×8 кварталов, шаг 22 м, GL Compatibility.

### Берём

1. **`build_route()` возвращает два параллельных массива: `points[]` и `gates[]`.**
   `gates[i]` — id перехода/светофора, который надо пройти на зелёный, чтобы
   попасть в `points[i]`; `-1` — свободный участок. Агент остаётся тупым
   автоматом: перед шагом смотрит гейт. ПДД получаются почти даром, и механизм
   расширяется (гейт как «уступи дорогу», «остановка», «шлагбаум»).
   Применяем и к пешеходам, и к машинам трафика.

2. **Геометрия генерируется ИЗ логической структуры, а не рядом с ней.**
   Список переходов заполняется при построении графа, а зебры, стойки и линзы
   рисуются из этого же списка. Разметка физически не может разъехаться с
   логикой. То же правило — для полос, стоп-линий и остановок.

3. **Смена состояния = запись в общий материал, а не обход нод.**
   В `capital` 448 линз светофоров живут в 4 MultiMesh, и смена фазы это 4
   присваивания. Нам нужны ПОФАЗНЫЕ перекрёстки, поэтому идём дальше:
   цвет линзы берётся из `INSTANCE_CUSTOM` в шейдере, а менеджер пишет
   `set_instance_custom_data` только тем перекрёсткам, у которых сменилась фаза.

4. **id узла — чистая функция от индекса, граф не хранится.**
   `node_id(gx, gz, local)`, ключ ребра `min * K + max`. Ноль аллокаций,
   тривиальная сериализация, дешёвый поиск «узел рядом с точкой».

5. **Поиск стартового узла ограничен своей клеткой.** Иначе ближайшим окажется
   узел за дорогой и первый шаг маршрута пройдёт по проезжей части мимо
   перехода. Для машин аналогично — только в своём сегменте полосы.

6. **Проверка «успею ли пройти» перед выходом на зебру** плюс аварийный таймаут
   ожидания и латч «уже иду» (чтобы не замереть посреди дороги при смене фазы).
   Три коротких правила, снимающие все дедлоки на переходах.

7. **Единый множитель времени** для мира, агентов, камеры и UI —
   пауза и ускорение работают везде одинаково, без `Engine.time_scale`.

8. **Headless-регрессии как исполняемая спецификация ПДД.** Самые ценные:
   «ни один негейтованный отрезок маршрута не пересекает полосу»,
   «машина тормозит перед стоп-линией», «ожидание на переходе не образует
   дедлок», «персонаж виден минимум с 3 ракурсов из 8». Пишем свои аналоги.

9. **Читаемость главного объекта**: силуэт сквозь стены через `next_pass` с
   `no_depth_test` (для машины игрока при перекрытии) и `fixed_size = true`
   для маркеров заказов — постоянный экранный размер на всей вилке зума.

10. **Кэш мешей по размеру** и общие материалы вместо уникальных на объект.

11. **Ambient нельзя оставлять чёрным при `sky_contribution < 1`** — иначе
    ночь проваливается в чёрное. Ночью подмешивать синеватый `ambient_light_color`.

### Не берём

1. **Один глобальный светофорный автомат на весь город.** Для игры про такси
    нужны пофазные перекрёстки со своим таймером — иначе не существует
    «зелёной волны», а она в оригинале есть (сдвиг фазы `-(isecX/64)*1.6`).
2. **Декоративный трафик**: без следования за лидером, без приоритетов, без
    поворотов, машины проезжают друг сквозь друга и сквозь пешеходов.
    У нас портируются 10 правил ИИ оригинала плюс граф полос с поворотными связями.
3. **Состояние машин в `set_meta`** — нетипизировано и медленно. У нас SoA-массивы.
4. **Отсутствие поворотов**: сразу закладываем поворотные связи перекрёстка
    на квадратичной Безье (как в оригинале: 58% прямо, 22% направо, 20% налево).
5. **Сборка всего мира кодом без единой сцены и за один кадр `_ready`.**
    У нас: данные в ресурсах, генератор в коде, уникальные объекты — сохранённые
    сцены, генерация в фоне с time-slicing.
6. **Агент на `y = 0` при верхе тротуара `y = 0.2`** — ставим по `height_at`.

### Как это меняет план этапа 3

Город остаётся **узнаваемым Пятигорском**: сетка 9×9 с шагом 64 м, реальные
координаты достопримечательностей, гора Машук с серпантином, районы и палитры
из оригинала. Меняется способ построения:
- `CityGraph` — единая структура: узлы полос + узлы тротуаров + переходы,
  id как функция индекса, `build_route()` с гейтами (для GPS, трафика и пешеходов).
- Вся разметка, зебры, бордюры, стойки и линзы — из этой структуры в MultiMesh.
- `Intersection` со своей фазой и «зелёной волной», линзы через `INSTANCE_CUSTOM`.
